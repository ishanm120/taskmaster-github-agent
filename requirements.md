# Requirements

## Source

Direct input from user story.

## Objective

Allow a user to mark an existing task as complete so that finished work is tracked and clearly distinguished from incomplete tasks.

## Functional Requirements

- FR-001: The system must allow a user to mark an existing task as complete.
- FR-002: The system must persist the task's completed state so the task remains marked as complete after the action is taken.
- FR-003: The system must visually distinguish a completed task from an incomplete task in the task list or related task views.

## Non-Functional Requirements

No explicit non-functional requirements identified.

## Dependencies and Constraints

- The task data model must support a completion status for each task.
- The requirement applies to tasks already created in the system.
- Completed tasks must remain part of the task list and remain identifiable as complete.

## Acceptance Criteria

1. A task can be marked complete by the user.
2. A completed task is visibly identified in the interface as distinct from an incomplete task.
